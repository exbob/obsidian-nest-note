# NestNote Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 创建一个不依赖第三方插件的 Obsidian 插件，将完整文档目录识别为嵌套文档，并通过侧边栏提供打开、新建、重命名、删除和附件归档能力。

**Architecture:** 使用 Obsidian Vault 文件系统作为唯一数据源。纯函数负责目录识别、Frontmatter 处理和受控链接生成；文件服务负责实际读写；事件协调器合并 Vault 事件并刷新侧边栏；`ItemView` 负责树形 UI 和用户操作。

**Tech Stack:** TypeScript、Obsidian Plugin API、esbuild、Vitest、原生 DOM/CSS。

## Global Constraints

- 管理整个 Vault 根目录。
- 不完整目录、普通 Markdown 文件和其他非文档文件均忽略。
- 目录的直接子项必须包含 `index.md` 和 `attachments/` 才能识别为文档。
- 目录名称是文档名称的唯一权威来源。
- 使用标准 Markdown 相对链接。
- 自动链接只维护受控区域，不修改用户正文。
- 保留 Obsidian 原生“插入附件”命令，不注册同名命令。
- 删除整个文档目录时使用 Obsidian 回收站机制。
- 不依赖 Dataview 或其他第三方 Obsidian 插件。
- 不维护独立的 JSON 数据库或缓存索引。
- 无法明确判断附件归属时，不自动移动附件。

## 文件结构

计划创建以下文件：

- `manifest.json`：Obsidian 插件清单。
- `package.json`、`package-lock.json`：构建和测试依赖。

- `src/main.ts`：插件生命周期、视图注册和命令装配。
- `src/types.ts`：文档节点、Vault 快照和服务接口。
- `src/domain/document-scanner.ts`：纯目录识别和文档树构建。
- `src/domain/frontmatter.ts`：Frontmatter 内容处理。
- `src/domain/children-links.ts`：受控子文档链接区域处理。
- `src/services/document-service.ts`：文档创建、重命名、删除和打开。
- `src/services/attachment-service.ts`：原生附件创建后的归档。
- `src/services/vault-event-coordinator.ts`：Vault 事件合并和刷新协调。
- `src/ui/document-tree-view.ts`：NestNote 侧边栏。
- `vitest.config.ts`：Node 与 DOM 测试环境配置。
- `tests/document-scanner.test.ts`、`tests/frontmatter.test.ts`、`tests/children-links.test.ts`：纯逻辑测试。
- `README.md`：安装、目录规则和手工验收说明。

- 目录识别、Frontmatter、链接、侧边栏、创建/重命名/删除、附件、事件同步和测试均有对应任务。

- 计划中没有未确定的占位步骤；所有测试均给出文件、命令和预期结果。
