# NestNote 功能增强设计

## 1. 目标

为 NestNote 增加可配置的文档层级限制和启动行为，改善新建子文档与树面板交互，并提供可直接复制安装的生产构建目录。

本次变更包含：

1. 新增 `build.sh`，支持生产构建发布和仅清除构建产物。
2. 默认最多支持五级子文档，并允许用户将限制调整为 `0～9`。
3. 在名称对话框中按 Enter 等同于点击“确认”。
4. 在 NestNote 面板提供全部展开/全部折叠按钮。
5. 默认在软件启动时打开 NestNote 面板，并允许关闭此行为。
6. 新增 UI 遵循 Obsidian 默认主题变量和交互样式。

## 2. 配置模型

新增设置模型：

```ts
interface NestNoteSettings {
  maxChildDepth: number;
  openPanelOnStartup: boolean;
}
```

默认值：

```ts
{
  maxChildDepth: 5,
  openPanelOnStartup: true
}
```

`maxChildDepth` 的有效范围为 `0～9`，仅接受整数。根文档深度为 `0`，因此：

- `0` 只显示根文档，不允许创建子文档；
- `5` 允许深度为 `1～5` 的子文档；
- `9` 是允许的最大配置值。

配置通过 Obsidian 插件设置页持久化。配置读取失败或字段缺失时分别回退到对应默认值；非法的用户输入不保存，并通过 Notice 或设置页校验信息提示。

## 3. 层级限制架构

扫描器 `scanDocuments` 增加可选配置参数，用于按文档路径计算深度。只有深度不超过 `maxChildDepth` 的完整文档才进入返回树；超出限制的文档及其子树不显示。

文档服务接收同一份设置读取接口或当前配置值。在 `create(parentPath, name)` 执行创建前计算新文档深度：

- 新建根文档深度为 `0`，不受子文档层级限制；
- 新建子文档的深度大于 `maxChildDepth` 时拒绝操作；
- 拒绝时不创建目录、文件或附件目录。

插件设置变更后执行一次全量扫描并刷新已打开的 NestNote 视图，使新的层级限制立即生效。扫描器和服务共享同一限制，避免隐藏节点仍可通过面板创建的问题。

## 4. 面板交互

`DocumentTreeView` 工具栏包含：

- 新建文档；
- 全部展开/全部折叠；
- 刷新。

全部展开/全部折叠按钮只针对当前树中存在子节点的文档：

- 只要有一个可展开节点未展开，按钮显示“全部展开”；
- 所有可展开节点均展开时，按钮显示“全部折叠”；
- 没有可展开节点时，按钮仍保持主题一致的禁用状态。

点击按钮只更新内存中的展开路径集合并重新渲染，不触发 Vault 扫描。普通刷新仍然保留仍存在节点的展开状态和选中状态。

名称对话框将确认逻辑集中为单一提交函数。输入框按 Enter 时阻止默认事件并调用该函数；空名称不提交。提交成功发起现有服务调用并关闭对话框，避免 Enter 与按钮事件造成重复提交。

所有新增控件继续使用 `setIcon()`、`aria-label`、Obsidian CSS 变量和 `.nestnote-*` 类名前缀，补充可见键盘焦点态与必要的禁用态，不引入 UI 框架或独立主题。

## 5. 启动生命周期

插件启动时先完成视图、命令、事件和设置页注册。布局准备完成后：

1. 执行首次扫描与元数据同步；
2. 当 `openPanelOnStartup` 为 `true` 时调用现有 `activateView()`；
3. 当其为 `false` 时不创建或激活 NestNote 面板。

设置页修改 `openPanelOnStartup` 只影响下一次插件或软件启动，不强制改变当前已打开的面板。

## 6. 构建与清除

根目录新增可执行 Bash 脚本 `build.sh`：

```text
./build.sh
```

执行 `npm run build`。只有构建成功后才创建或清空 `./nest-note/`，并复制：

```text
main.js
manifest.json
styles.css
```

```text
./build.sh clean
```

只清除以下构建产物：

- 根目录 `main.js`；
- 根目录 `main.js.map`（若存在）；
- `./nest-note/` 目录。

`clean` 不执行构建，也不删除源码、依赖或项目配置。未知参数应报错并返回非零状态。

## 7. 错误处理

- 最大层级输入不是 `0～9` 的整数时不保存；
- 创建超出层级限制的子文档时通过现有 Notice 机制提示，并保持树状态；
- 名称对话框提交空值时保持打开；
- 面板操作失败时不伪造成功状态，不清除现有展开或选中状态；
- 构建失败时立即返回失败状态，不复制新的发布文件；
- 清除命令遇到不存在的产物视为成功，避免重复清理失败。

## 8. 测试设计

新增或调整自动化测试：

### 纯逻辑测试

- 默认最大层级和自定义 `0～9` 层级；
- 超出最大深度的文档不出现在扫描结果；
- `0` 层级只返回根文档；
- 非法层级值被拒绝或回退。

### 文档服务测试

- 达到最大子文档层级时创建操作失败；
- 失败前不产生任何新目录或文件；
- 未达到限制时根文档和子文档仍按原行为创建。

### 视图测试

- Enter 提交名称并关闭对话框；
- 全部展开会展开每个可展开节点；
- 全部折叠会清除每个可展开节点的展开状态；
- 动态按钮标签和图标随状态变化；
- 面板控件继续具有可访问标签和图标。

### 插件生命周期测试

- 默认布局准备后自动激活 NestNote 面板；
- 关闭启动选项后不自动激活面板；
- 设置变更后按新层级刷新视图。

### 构建脚本测试

- 默认模式成功构建并产生三个安装文件；
- `clean` 只删除约定的构建产物且不构建；
- 构建失败时发布目录不会被更新。

## 9. 不变更范围

- 不改变 Vault 作为唯一数据源的设计；
- 不引入第三方 Obsidian 插件或 UI 框架；
- 不改变普通文件和不完整目录的识别规则；
- 不改变附件归档、受控链接和回收站行为；
- 不删除或覆盖 Obsidian 原生“插入附件”命令。
