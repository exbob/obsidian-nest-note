# NestNote 资源管理器面板

## 1. 目标

新增独立侧边栏「资源管理器」面板，浏览当前打开的 NestNote 文档下指定文件夹（默认 `files/`）内的文件与子文件夹。支持逐层进入、插入 wiki 链接、系统剪贴板复制/粘贴、删除前关联检查，以及在系统资源管理器中打开路径。

不改动现有文档树面板的核心行为；设置页中资源管理器选项与现有 NestNote 选项分区显示。

## 2. 已确认的选择

- **实现方式：** 独立 `ItemView`（方案 A），不嵌进文档树，不复用原生文件浏览器。
- **非 NestNote / 无活动文件：** 显示空状态「请打开一篇 NestNote 文档」，不列出文件、不自动创建目录。
- **关联检查范围：** 删除前只检查**当前打开文档**的 `index.md` 正文是否引用目标路径（及删除文件夹时其子孙路径）。
- **复制/粘贴：** 对接系统剪贴板，可与系统资源管理器互通；同名冲突提示并取消。
- **资源根不存在：** 在已解析到 NestNote 文档时自动创建配置的根文件夹，再显示空列表。
- **文件夹右键：** 与文件相同（插入文档、复制、粘贴、删除）；插入用 `[[path|foldername]]`。
- **插入链接 path：** 相对当前 `index.md`（例如 `files/photo.png`），不是库根绝对 wiki 路径，也不是仅文件名。
- **面板默认位置：** 右侧边栏；可通过设置改为左侧。
- **启动行为：** 「启动时打开 NestNote 面板」只影响文档树，不自动打开资源管理器。
- **路径栏显示：** 相对资源根的当前路径（根为配置名，如 `files` 或 `files/images`），不强制带文档目录名。

## 3. 架构与组件

| 单元 | 职责 |
|------|------|
| `FileExplorerView` | UI：路径栏、单层列表、右键菜单、双击；不直接写 vault |
| `FileExplorerService` | 解析当前 NestNote 文档、保证根目录存在、列一层、插入链接、关联检查、删除 |
| `DesktopFileActions`（扩展） | 已有默认应用打开 / 系统资源管理器；新增系统剪贴板文件复制与粘贴 |
| Settings | `fileExplorerSide: "left" \| "right"`（默认 `"right"`）；`fileExplorerRoot: string`（默认 `"files"`） |
| Plugin (`main.ts`) | 注册视图与命令；监听活动文件变化并通知面板刷新；侧栏设置变更时移动面板 |

边界：文档树与资源管理器互不依赖。资源管理器只依赖「当前 NestNote 文档路径 + 相对根目录名」。

视图类型：`VIEW_TYPE_NESTNOTE_FILES = "nestnote-file-explorer"`。  
图标：`folder`。显示名：资源管理器 / File explorer。

## 4. 交互与 UI

### 4.1 面板结构

- **顶部路径栏：** 左侧「向上」；中间当前相对路径；右侧「在系统资源管理器中打开当前路径」。
- **列表：** 一次只显示当前文件夹内容；文件夹在前、文件在后，同组按名称排序；文件名必须带后缀；按类型显示图标（文件夹 / 图片 / 音视频 / 文本 / 通用）。
- **单击：** 选中，不打开。
- **双击文件夹：** 进入该层。
- **双击文件：** 用系统默认应用打开。
- **切换活动文档：** 面板重置到该文档的资源根并刷新。

### 4.2 空状态

| 条件 | 显示 |
|------|------|
| 无活动文件，或活动文件不属于 NestNote 文档 | 「请打开一篇 NestNote 文档」 |
| 已打开 NestNote，根已创建且当前层无条目 | 空列表 |
| 自动创建根失败等错误 | Notice + 错误空状态文案 |

### 4.3 导航

- 在根目录时「向上」不可用（或无效）。
- 「在系统资源管理器中打开」：打开当前浏览路径对应的本地目录；无本地绝对路径时 Notice（与文档树一致）。

## 5. 右键菜单与文件操作

文件与文件夹菜单相同，顺序：

```
插入文档
─────────────
复制
粘贴
─────────────
删除
```

| 项 | 行为 |
|----|------|
| 插入文档 | 在当前 Markdown 编辑器光标处插入链接。音视频扩展名用 `![[path\|name]]`；其他文件与文件夹用 `[[path\|name]]`。`path` 相对当前 `index.md`；`name` 为带后缀的显示名。无编辑焦点时 Notice。 |
| 复制 | 将选中项写入系统剪贴板。 |
| 粘贴 | 粘贴到**当前浏览路径**；目标已存在同名则提示并取消。 |
| 删除 | 先在当前 `index.md` 检查引用（文件夹则检查其下所有子孙路径）；再二次确认；确认后 `trash`（走 Obsidian 回收站偏好）。有关联时确认文案须标明存在引用。 |

音视频扩展名集合（实现时固定列表，可含常见：`mp3` `wav` `ogg` `m4a` `flac` `mp4` `webm` `mov` `mkv` `avi` 等）。

## 6. 设置与命令

设置页在现有三项之后增加分隔标题「资源管理器」，其下：

| 设置 | 默认 | 说明 |
|------|------|------|
| 面板位置 | 右侧 | `left` / `right`；变更后将面板移到对应边栏 |
| 文档内资源文件夹 | `files` | 相对文档目录的单段路径名；禁止 `..`、绝对路径、空串、含 `/` 或 `\` 的多级路径；非法值归一化为 `files` |

命令：`NestNote: 打开资源管理器`（打开或聚焦该面板到配置的边栏）。

不提供「启动时自动打开资源管理器」设置。

## 7. 数据流

1. 插件监听 `active-leaf-change` / 活动文件变化。
2. 解析活动文件所属 NestNote 文档目录（与现有附件/文档识别逻辑一致：需具备 `index.md` + `attachments/` 约定）。
3. 若是 NestNote：确保 `{documentPath}/{fileExplorerRoot}` 存在；将根与当前相对子路径交给 View 刷新。
4. 若不是：View 显示空状态，清空列表与浏览栈。
5. Vault 的 create/delete/rename/modify：若影响当前文档资源根下路径，刷新当前层列表；不强制把用户从子目录弹回根。

## 8. 错误处理

- 系统剪贴板不可用、粘贴冲突、插入无焦点、无本地路径、打开外部失败 → Notice，不静默失败。
- 复制/打开系统资源管理器成功时不弹 Notice（与文档树桌面操作一致）。
- 删除失败 → Notice，列表保持可刷新状态。

## 9. 测试

对齐现有 vitest + stub 风格：

- `normalizeNestNoteSettings`：`fileExplorerSide` / `fileExplorerRoot` 非法回退。
- 链接生成：相对 `index.md`；音视频 embed vs 普通 wiki；文件夹链接。
- 关联检测：有/无引用；文件夹子孙路径。
- 列目录：仅一层；文件夹优先排序。
- 服务层桌面剪贴板通过 mock，不测真实 Electron。

## 10. 非目标

- 不在本面板内新建空文件/重命名（除粘贴产生的副本）。
- 不拖拽排序或拖入编辑器（插入仅通过右键）。
- 不扫描或管理 `attachments/`（除非用户把根设为该名；默认仍为 `files`）。
- 不改文档树拖放、子文档层级等现有逻辑。
